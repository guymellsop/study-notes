No UPROPERTY at all (like IdleElapsedTime) is fine for plain numbers. For a UObject pointer it's a crash waiting to happen: see GC.

Asserts: check, checkf, ensure

MacroOn failureIn Shipping builds
check(x)Crash with file/lineRemoved (not evaluated)
checkf(x, TEXT("msg"))Crash with your messageRemoved
ensure(x) / ensureMsgfLogs a callstack once, carries onStill evaluated, doesn't break

The course uses checkf(InputConfigDataAsset, ...) because a missing data asset is a setup error: crash loudly now in the editor, with a message that says what to fix. Never put code with side effects inside check(). It disappears in Shipping.

Header tricks

  • Forward declaration: class USpringArmComponent; at the top of a header says "this type exists". It's enough for a pointer, so the heavy #include moves to the .cpp. That makes compiles faster and avoids include chains (includes page).
  • class UInputComponent* PlayerInputComponent in a parameter is an inline forward declaration: the same thing in one go.
  • FORCEINLINE: "really inline this" for tiny getters, so there's no function-call overhead.
  • #pragma region Inputs … #pragma endregion: only folds code in the IDE. The compiler ignores it.
  • //~ Begin APawn Interface: an Epic comment convention marking a group of overrides from one base class.
  • GENERATED_BODY(): where Unreal's header tool pastes the reflection code. It also gives you Super (the parent class) and ThisClass.
  • #include "X.generated.h" must be the last include in a reflected header.

The Debug helper, closely

namespace Debug {
    static void Print(const FString& Msg, const FColor& Color = FColor::MakeRandomColor(), int32 InKey = -1) {
        if (GEngine) {
            GEngine->AddOnScreenDebugMessage(InKey, 7.f, Color, Msg);
            UE_LOG(LogTemp, Warning, TEXT("%s"), *Msg);
        }
    }
}
  • const FString&: pass by const reference, so no copy of the string (refs and const).
  • Default arguments: Debug::Print("hi") picks a random colour and key −1.
  • Key −1 = always add a new line. The same positive key replaces the previous message, which is great for values that change every frame.
  • *Msg: FString's operator* gives the raw TCHAR* that %s needs. Forgetting the * is a classic crash/garbage bug.
  • static in a header: each .cpp that includes it gets its own private copy. It works; inline would share one copy. Harmless for a debug helper.
  • if (GEngine): GEngine can be null very early in startup and in some commandlets.

Quiz yourself

EditDefaultsOnly vs EditAnywhere?

Defaults-only: editable in the Blueprint class, not per placed instance. Anywhere: both.

Why are component pointers VisibleAnywhere rather than EditAnywhere?

You want to edit the component's properties in the Details panel, not reassign the pointer to a different object.

What does AllowPrivateAccess allow?

A private C++ member to still be exposed as BlueprintReadOnly/ReadWrite.

check vs ensure: which one crashes, and which survives in Shipping?

check crashes but is compiled out of Shipping. ensure logs once and carries on, and is still evaluated in Shipping.

Why is it dangerous to write check(DoSetup())?

In Shipping the whole expression disappears, so DoSetup() never runs.

When is a forward declaration enough, and when do you need the include?

Enough for pointers and references to the type. You need the full include to call its functions, access members, inherit from it, or hold it by value.

Why *Msg in UE_LOG(..., TEXT("%s"), *Msg)?

%s needs a TCHAR*. * on an FString returns its raw character pointer.

What does a positive key do in AddOnScreenDebugMessage?

A new message with the same key replaces the old one, instead of stacking a new line.
