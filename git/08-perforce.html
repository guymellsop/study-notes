Perforce refresher

What most studios use, mapped onto the git you know · 9 min

In one breath

Perforce (Helix Core) is centralised: one server holds the history, and your workspace syncs the files you map. You check out a file before editing (which can lock it), group edits in a changelist, and submit straight to the server. There's no local commit and no push. Shelving shares work without submitting it. Streams are its branches.

The classic mix-up: "revert"

In Perforce, Revert means "throw away my local changes to this file and undo the checkout". In git, revert means "make a new commit that undoes an old commit". A git user who reverts in P4V expecting the git meaning loses their edits.

A normal day in Perforce

  1. Get Latest (sync) before starting.
  2. Check out the files you'll touch. For assets, Unreal does this for you if Revision Control is connected (it asks, or auto-checks out on modify).
  3. Keep separate tasks in separate numbered changelists, not everything in the default one.
  4. Shelve for review if the team reviews (Swarm), then address comments.
  5. Sync again, resolve anything newer, build, then Submit with a clear description.
  6. Don't leave files checked out overnight that others need, especially exclusive ones. Teams notice.

Perforce + Unreal specifically

  • Revision Control in the editor (bottom-right of the editor): connect to Perforce, and the Content Browser shows checkout status icons. Saving an asset prompts to check it out.
  • Exclusive checkout on binary assets (typemap binary+l for .uasset/.umap) is why Perforce is the studio default: two people can never edit the same Blueprint.
  • Unreal Game Sync (UGS): Epic's tool for syncing to a CL that's known to build, often with precompiled binaries, so artists don't compile C++.
  • Typemap: server-side rules for file types (binary, exclusive lock, how many old revisions to keep).
In an interview

"Have you used Perforce?" → "Yes, on [project]: check out, changelists, submitting, with exclusive checkout on assets. These days I mostly use git with LFS and locking, so I'm comfortable with both models: centralised with locking for binary-heavy work, and branches with pull requests for code." Quiz yourself

What's a workspace, and why does it have a mapping?

Your local folder plus the list of depot paths it contains, so you can sync only the parts of a huge depot you need.

Git's commit + push is what single step in Perforce?

Submit (a changelist).

What does Revert mean in Perforce, and why is it dangerous for git users?

It discards your local changes and undoes the checkout. Git's revert creates an undo commit, so the same word could cost you your edits.

What's shelving for?

Storing a changelist on the server without submitting it, for code review, handing work over, or backup.

Why do studios use exclusive checkout for .uasset?

Binary assets can't be merged, so only one person may edit one at a time.

Streams: what do "merge down" and "copy up" mean?

Merge down: bring changes from a more stable stream into a less stable one. Copy up: promote finished work to a more stable stream.

What's Unreal Game Sync for?

Syncing to a changelist known to build, often with precompiled binaries, so non-programmers can work without compiling.

Why use separate numbered changelists?

To keep unrelated work apart, so each submit (and its review) is one coherent change, like one-idea git commits.
